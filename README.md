# Тестирование HTTP-сервера «Поиск кафе» на Go 
Проект посвященный комплексному тестированию HTTP-сервера, возвращающего список кафе в зависимости от переданных GET-параметров (`city`, `count`, `search`). В проекте реализовано полное тестовое покрытие как для позитивных/негативных сценариев, так и для сложной логики фильтрации и пагинации данных.

##  Описание проекта
Проект демонстрирует навыки написания табличных тестов (Table-Driven Tests) для веб-сервисов на Go с использованием стандартного пакета `net/http/httptest` и продвинутой библиотеки утверждений `://github.com`.

### Тестируемый функционал сервера (эндпоинт `/cafe`):
*   `city` (string) — Обязательный параметр города (`moscow` или `tula`).
*   `count` (int) — Ограничение на количество выводимых кафе.
*   `search` (string) — Регистронезависимый поиск кафе по подстроке в названии.

---

##  Архитектура тестового файла `main_test.go`

Файл с тестами содержит 4 ключевые функции, покрывающие все требования технического задания:

### 1. `TestCafeWhenOk()`
*   Проверка базового позитивного сценария. Убеждается, что сервер возвращает статус `200 OK` и непустое тело ответа при корректных параметрах.

### 2. `TestCafeNegative()`
*   Проверка негативных сценариев (например, передача несуществующего города или отсутствие обязательных параметров). Убеждается в корректности кодов ошибок.

### 3. `TestCafeCount()`
*   **Табличный тест** для проверки лимита вывода (`count`). 
*   Проверяет следующие кейсы:
    *   `count=0` — ожидается 0 кафе в ответе.
    *   `count=1` — ожидается ровно 1 кафе.
    *   `count=2` — ожидается ровно 2 кафе.
    *   `count=100` — ожидается верхний лимит (общее количество кафе в городе через `len(cafeList[city])`).
*   Строка ответа парсится в слайс с помощью `strings.Split()`, после чего валидируется его длина.

### 4. `TestCafeSearch()`
*   **Табличный тест** для проверки поиска по подстроке (`search`) без учета регистра.
*   Проверяет кейсы по городу Москва:
    *   `search=фасоль` — 0 найденных кафе.
    *   `search=кофе` — 2 найденных кафе.
    *   `search=вилка` — 1 найденное кафе.
*   Каждое название в ответе проверяется с помощью `strings.Contains()` с предварительным приведением строк к единому регистру через `strings.ToLower()`.

##  Примененный технологический стек & Фишки

*   **Пакет `httptest`:** Создание изолированных HTTP-запросов (`httptest.NewRequest`) и запись ответов (`httptest.NewRecorder`) без реального запуска сервера на сетевом порту.
*   **Библиотека `testify`:** 
    *   `require.Equal()` — для критических проверок (если статус ответа не `200 OK`, тест немедленно прерывается).
    *   `assert.Equal()` / `assert.True()` — для проверки содержимого ответа без остановки выполнения остальных тест-кейсов.
*   **Пакет `strings`:** Парсинг результатов (`strings.Split`) и регистронезависимая валидация подстрок (`strings.ToLower`, `strings.Contains`).

##  Инструкция по запуску тестов

1. Склонируйте репозиторий:
   ```bash
   git clone https://github.com
   ```
2. Перейдите в папку проекта:
   ```bash
   cd название_папки_проекта
   ```
3. Запустите тестирование одной командой:
   ```bash
   go test -v .
   ```
   Флаг `-v` (verbose) покажет детальный отчет по каждой тестовой функции.
